* ICMP 메시지 추가 정리 - Destination unreachable / Redirect / Time Exceeded

1. 프로토콜이란

  • 네트워크에서 장비나 프로그램끼리 통신하기 위해 정해둔 규칙의 집합
  • 통신에서 발생하는 특정 문제를 해결하기 위한 규칙이다.
  • 예를 들면:
    • FTP: 파일을 주고받는 규칙
    • SMTP: 이메일을 보내고 전달하는 규칙
    • POP3: 메일 서버에서 메일을 내려받는 규칙
    • IMAP: 서버에 있는 메일함을 동기화하며 관리하는 규칙
    • ICMP: IP 통신 중 오류나 상태를 알려주는 규칙
  • 프로토콜은 역할을 나눈다.
    • 실제 통신에서는 하나의 프로토콜이 모든 일을 처리하지 않는다.
    • 상황에 따라 필요한 역할이 다르고, 그 역할에 맞는 프로토콜이 사용된다.
  • RFC
    • Request for Comments
    • 인터넷 기술과 프로토콜에 대한 표준이나 기술 문서를 설명하는 문서 체계
    • 그 중 일부가 인터넷 표준으로 인정된다.
    • 그 프로토콜이 원래 어떤 문제를 해결하려고 만들어졌고(설계 의도),
      어떤 방식으로 동작하도록 정의되었는지 확인할 수 있다.

2. 계층별 프로토콜의 특징

TCP/IP 계층 OSI 대응 대표 프로토콜 프로토콜의 관심사
응용 계층 5~7계층 HTTP, HTTPS, FTP, SMTP, POP3, IMAP,
DNS, DHCP, SSH, Telnet, SNMP		 실제 매체에서 어떻게 전달할 것인가
전송 계층 4계층 TCP, UDP 어느 프로그램에게, 어떤 방식으로 전달할 것인가
인터넷 계층 3계층 IP, ICMP, ARP, 라우팅 프로토콜 어느 네트워크의 어느 호스트로 보낼 것인가
네트워크 접근 계층 1~2계층 Ethernet, Wi-Fi, PPP 등 실제 매체에서 어떻게 전달할 것인가
  • 네트워크 통신은 하나의 프로토콜이 모든 일을 처리하는 것이 아니라,
    계층별로 역할을 나누어 처리한다.
  • 각 계층의 프로토콜은 자기 계층의 역할에 집중하고,
    아래 계층의 기능을 이용해 위 계층에 서비스를 제공한다.

네트워크 접근 계층

프로토콜/표준 특징
Ethernet 유선 LAN에서 많이 사용하는 데이터링크 계층 기술
Wi-Fi 무선 LAN 통신을 위한 IEEE 802.11 계열
PPP 두 지점 간 직접 연결에 사용되는 프로토콜
ARP IP 주소를 MAC 주소로 변환하는 데 사용됨
  • 같은 네트워크 안에서 실제로 데이터를 전달하는 규칙과 관련

인터넷 계층

프로토콜 특징
IP 목적지 IP 주소를 기준으로 패킷을 전달
ICMP IP 통신 중 오류나 상태를 알려줌
RIP / OSPF 내부 네트워크 라우팅 프로토콜
BGP 인터넷 규모의 라우팅 프로토콜
  • 서로 다른 네트워크 사이에서 목적지까지 패킷을 전달하는 역할
  • IP는 패킷을 목적지까지 보내려고 하지만, 전송 성공을 보장하지 않는다.
    전송 중 문제가 생겼을 때 그 상태를 알려주는 데 ICMP가 사용된다.

전송 계층

프로토콜 특징
TCP 연결 지향, 신뢰성 보장, 순서 보장, 재전송
UDP 비연결형, 빠르고 단순함, 신뢰성 보장은 응용에서 처리
  • 프로세스와 프로세스 간 통신 담당
  • 핵심은 포트번호, 신뢰성, 연결성
  • FTP, SMTP, POP3, IMAP은 응용 계층의 프로토콜이지만,
    실제 데이터를 주고 받을 때는 전송 계층의 TCP를 사용한다.

응용 계층

프로토콜 특징
HTTP/HTTPS 웹 페이지 요청과 응답
FTP 파일 전송
SMTP 이메일 송신 및 서버 간 전달
POP3 메일 서버에서 클라이언트로 메일 가져오기
IMAP 서버 메일함 접근 및 동기화
DNS 도메인 이름을 IP 주소로 변환
DHCP IP 주소 등 네트워크 설정 자동 할당
SSH 보안 원격 접속
Telnet 원격 접속, 평문 기반이라 보안 취약
SNMP 네트워크 장비 관리
  • 사용자가 실제로 이용하는 서비스에 가장 가까운 프로토콜

3. FTP

  • File Transfer Protocol
  • 네트워크상에서 클라이언트와 서버 사이에 파일을 전송하기 위한 프로토콜
  • RFC 959:
    • 호스트 간 파일을 효율적이고 신뢰성 있게 전송하고
      원격 파일 저장소를 사용할 수 있게 하는 것이 주요 목적이라고 설명한다.
  • 주요 명령어
    • USER, PASS, LIST, RETR, STOR

특징: 제어채널과 데이터채널 분리

  • FTP는 연결을 하나만 쓰지 않고, 목적에 따라 연결을 나눈다.
구분 역할 일반적인 포트
제어채널 로그인, 명령어, 응답 처리 TCP 21
데이터채널 실제 파일 목록/파일 내용 전송 기본 TCP 20 또는 별도 포트

동작흐름

  • 예를 들면 사용자가 FTP 서버에서 파일을 다운로드할 때:
    1. 클라이언트가 FTP 서버에 접속
    2. 제어채널 연결
    3. 사용자 인증
    4. LIST, RETR, STOR 같은 명령 전송
    5. 데이터채널 연결
    6. 파일 목록 또는 파일 데이터 전송
    7. 데이터채널 종료
    8. 제어채널은 계속 유지되거나 종료
  • FTP는 명령을 주고받는 통로와 실제 파일이 이동하는 통로가 분리되어 있기 때문에,
    제어채널 연결과 데이터채널 연결이 순차적으로 각각 필요하다.

모드종류

  • FTP는 데이터채널을 여는 방식에 따라 Active Mode/Passive Mode로 나뉜다.
구분 특징 제어 채널 데이터 채널
Active Mode 서버가 클라이언트 쪽으로 데이터 연결을 시도 21번 20번
Passive Mode 클라이언트가 서버가 알려준 포트로 데이터 연결을 시도 21번 서버 지정 랜덤 포트

보안관점

  • FTP는 전통적으로 사용자 이름, 비밀번호, 파일 내용이 평문으로 오갈 수 있어서 보안에 취약하다.
  • 그래서 실제 운영 환경에서는 보안이 필요한 경우 FTPS/SFTP 같은 대안을 사용한다.
  • SFTP는 FTP의 보안을 강화한 버전이라기보다,
    SSH 기반의 별도 파일 전송 프로토콜에 가깝다.

4. 이메일 프로토콜: SMTP/POP3/IMAP

이메일 전송 흐름

보낸 사람 메일 클라이언트
        ↓ SMTP
보낸 사람 메일 서버
        ↓ SMTP
받는 사람 메일 서버
        ↓ POP3 또는 IMAP
받는 사람 메일 클라이언트

프로토콜별 역할

프로토콜 역할 핵심 이미지
SMTP 메일 송신 및 서버 간 전달 보낸다
POP3 서버의 메일을 클라이언트로 가져옴 내려받는다
IMAP 서버 메일함을 클라이언트에서 동기화하며 관리 동기화한다

4-1. SMTP

항목 내용
이름 Simple Mail Transfer Protocol
역할 이메일 송신, 서버 간 메일 전달
계층 응용 계층
전송 계층 TCP
대표 포트 25, 메일 제출은 587도 사용
핵심 명령 HELO/EHLO, MAIL FROM, RCPT TO, DATA, QUIT
  • 메일을 보내고 전달하는 프로토콜
  • SMTP의 메일 트랜잭션은 크게
    • MAIL 명령으로 송신자를 지정하고,
    • RCPT 명령으로 수신자를 지정한 뒤,
    • DATA 명령으로 실제 메일 데이터를 전송하는 구조이다.

4-2. POP3

항목 내용
이름 Post Office Protocol Version 3
역할 서버에 도착한 메일을 클라이언트로 가져오기
계층 응용 계층
전송 계층 TCP
대표 포트 110
특징 다운로드 중심, 서버 조작 기능은 제한적
  • 메일 서버에 도착한 메일을 클라이언트로 가져오는 프로토콜
  • 간단하게는 메일을 내 기기로 내려받는 방식에 가깝다.
  • 때문에 단일 기기에서 메일을 확인하던 과거 환경에 잘 맞는 방식이다.
  • RFC 1939:
    • POP3는 보통 서버가 보관 중인 메일을 워크스테이션이 가져오도록 하는 데 사용된다.
    • 서버 위에서 메일을 복잡하게 조작하는 기능을 제공하려는 것은 아니다.

4-3. IMAP

항목 내용
이름 Internet Message Access Protocol
역할 서버의 메일함을 클라이언트에서 접근·동기화
계층 응용 계층
전송 계층 TCP
대표 포트 143
특징 서버 중심 관리, 여러 기기 동기화에 유리
  • 서버의 메일함을 클라이언트에서 접근하고 동기화하는 프로토콜
  • IMAP4rev2는 클라이언트가 서버의 전자메일 메시지에 접근하고 조작할 수 있게 한다.
  • 원격 메일함을 로컬 폴더처럼 다루고
    오프라인 클라이언트가 다시 동기화할 수 있는 기능도 제공한다.
  • 간단하게 말하면 단순히 내려받는 것보다,
    메일함을 여러 기기에서 동기화하면서 관리하는 방식에 가깝다.
  • RFC 9051:
    • IMAP이 메일 게시/발송 기능을 직접 정의하지 않는다.
      그 기능은 별도의 mail submission 프로토콜이 담당한다.

4-4. 차이점 정리

구분 SMTP POP3 IMAP
주요 역할 메일 송신/전달 메일 가져오기 메일함 동기화/관리
방향 클라이언트 → 서버, 서버 → 서버 서버 → 클라이언트 서버 ↔ 클라이언트
서버 보관 전송 중심 내려받고 삭제하는 모델이 기본적 서버 보관 중심
여러 기기 사용 해당 없음 불편할 수 있음 유리함
대표 포트 25 / 587 110 143
비유 우체국 발송/배송 우편함에서 편지 꺼내오기 서버 우편함을 원격으로 관리

5. ICMP

  • Internet Control Message Protocol
  • 위에 나온 프로토콜들과 달리 응용 계층 프로토콜이 아니라,
    인터넷 계층에서 IP 통신의 오류나 상태를 알려주는 제어·진단용 프로토콜
  • RFC 792:
    • ICMP의 목적은 IP를 신뢰성 있는 프로토콜로 만드는 것이 아니라,
      통신 환경에서 발생한 문제에 대한 피드백을 제공하는 것이다.
    • ICMP 메시지는 IP 헤더를 사용해 전송된다.
    • ICMP 메시지의 첫 번째 필드인 Type 값에 따라 메시지 형식이 달라진다.
  • TCP/UDP 위에서 동작하는 게 아니라 IP 계층에서 동작하므로,
    일반적인 의미의 TCP/UDP 포트 번호를 사용하지 않는다.
  • 메시지 구조: Type과 Code로 구분
  • 활용 예시: ping, traceroute
  • 주의점: 보안 정책상 차단될 수 있음

대표 ICMP 메시지

Type 메시지 의미
0 Echo Reply Echo 요청에 대한 응답
3 Destination Unreachable 목적지 도달 불가
5 Redirect 더 적절한 경로 안내
8 Echo Echo 요청, ping에서 사용
11 Time Exceeded TTL 초과 등 시간 초과
12 Parameter Problem IP 헤더 등 매개변수 문제

6. 정리

계층별 프로토콜과 특징 정리

계층 역할 중점/대표 프로토콜 정리
네트워크 접근 계층 같은 네트워크 내 실제 전달 Ethernet, Wi-Fi, ARP 프레임, MAC 주소 기반 전달
인터넷 계층 네트워크 간 패킷 전달 IP, ICMP IP는 전달, ICMP는 오류/상태 보고
전송 계층 프로세스 간 전송 TCP, UDP TCP는 신뢰성, UDP는 단순성과 속도
응용 계층 사용자 서비스 제공 FTP, SMTP, POP3, IMAP, HTTP, DNS 파일, 메일, 웹 등 목적별 프로토콜

프로토콜 포트 번호 정리

프로토콜 역할 포트
FTP 제어 명령/응답 21
FTP 데이터 파일 데이터 20
SMTP 메일 송신 25
POP3 메일 수신/다운로드 110
IMAP 메일 접근/동기화 143
ICMP 오류/상태 메시지 포트 사용 안 함
  • 계층별 프로토콜은 각 계층의 역할에 따라 서로 다른 목적과 특징을 가진다.
  • 각 프로토콜의 포트 번호를 정확히 아는 것 또한 중요하다.
    단순 암기가 아니라, 패킷 분석/보안 관제/취약점 진단에서 어떤 서비스가 동작하는지 파악하는 기준이 된다.
